# Jarvis — заметки для Claude

Читается в начале каждой сессии Claude Code с этим репозиторием, в том числе
облачной. Здесь только правила работы с кодом: репозиторий публичный, личных
данных сюда не писать.

## Язык

Владелец пишет по-русски (иногда по-украински) — отвечать по-русски.
Сообщения коммитов — по-английски, как в истории репозитория.

## С чего начать

- Ветка разработки — `amazonq`. `main` отстаёт и обновляется только на релизе.
- План — `docs/ROADMAP.md`. В нём только то, что осталось сделать: этапы
  M1–M6, бэклог P1–P3, раздел «Проверка дома». Брать задачу оттуда. Закрыл
  задачу — удалить её из плана в том же коммите; новую находку — добавить в
  бэклог.
- Задачи помечены **[Работа]** (делается и проверяется тестами), **[Дом]**
  (нужен живой Jarvis: GPU, Ollama, микрофон) и **[Работа → Дом]** (код здесь,
  проверка голосом дома).
- Устройство кода и правила — `CONTRIBUTING.md`, `SPEC.md`, `BUILD.md`.

## Облачная сессия (Linux, без живого Jarvis)

- Нет GPU, Ollama, микрофона и данных пользователя. Брать **[Работа]** и
  кодовую часть **[Работа → Дом]**.
- Тесты, завязанные на Windows, на Linux пропускаются или не запускаются —
  это нормально; финальный прогон делается дома на Windows.
- Каждую задачу, которую нужно проверить голосом, записать в раздел
  «Проверка дома» в `docs/ROADMAP.md`: фраза и что должно произойти.

## Перед коммитом

```
python -m ruff check jarvis tests
python -m pyright <изменённые файлы>
python -m pytest -q
```

- В `jarvis/` есть старые ошибки pyright (задача M2-1 в плане): проверять
  только свои файлы и не добавлять новых.
- Одно исправление — один коммит. К исправлению — тест, который падает без
  него (проверить: `git stash` изменения кода, прогнать тест, `git stash pop`).
- Пушить в `amazonq`, когда владелец просит или одобрил.

## Чего не делать

- Не коммитить личные файлы владельца: `my_preferences.yaml`, образцы голосов,
  базы памяти, скрипты и отчёты в корне (`home_check*.ps1`, `run_jarvis.ps1`,
  `home_report.txt`, `home_test_run.txt`, `report2.txt`).
- Не менять таблицу переходов состояний в `jarvis/core/state_machine.py` —
  это контракт из `SPEC.md`.
- Не делать нечёткое сопоставление названий в `open_targets.py`: «гугл»
  превращался в «Google Chrome».

## Когда владелец пишет «проверь» (только дома, на его ПК)

Прочитать живую сессию: `%APPDATA%\Jarvis\logs\jarvis.log.jsonl` (время в UTC;
до 2026-11-05 — `jarvis.log.jsonl` в корне репозитория, вперемешку с тестами),
`%APPDATA%\Jarvis\logs\jarvis.log` (трейсбеки),
`%APPDATA%\Jarvis\debug\last_llm_request.json` (запрос к модели).
Сверить с «Проверкой дома» в плане, проверенное убрать, найденное — в бэклог.
