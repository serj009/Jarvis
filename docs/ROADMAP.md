# Jarvis — план разработки (ветка `amazonq`)

Живой документ: обновляй его в том же коммите, где закрываешь или добавляешь задачу.
Последнее обновление: 2026-11-03.

## Как работать в двух местах

| | Дом | Работа |
|---|---|---|
| Что есть | Полная среда: GPU, Ollama + `qwen3:8b`, микрофон, модели STT/TTS/wake word | Только код и тесты |
| Что делать | Живые проверки голосом, чтение логов, настройка порогов | Код, юнит-тесты, рефакторинг, документация |
| Как понять, что готово | Поведение в логе живой сессии | `ruff`, `pyright` и `pytest` зелёные |

Каждая задача ниже помечена:

- **[Работа]** — можно сделать и проверить тестами без домашнего ПК;
- **[Дом]** — нужен живой запуск Jarvis;
- **[Работа → Дом]** — код пишется на работе, финальная проверка голосом дома.

### Цикл

1. **Работа:** `git pull`, взять задачу, написать код и тест, прогнать проверки, `git push`.
2. **Дом:** `git pull`, запустить Jarvis с дампом запросов (см. ниже), проговорить фразы из раздела «Проверка дома», закрыть Jarvis.
3. **Дом:** попросить Claude «проверь логи» (или прочитать их самому, см. «Где логи»).
4. Обновить этот файл: закрытые задачи перенести в «Сделано», новые находки — в бэклог.

### Среда на работе (один раз)

```powershell
git clone https://github.com/serj009/Jarvis.git
cd Jarvis
git checkout amazonq
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Python 3.14, как дома. Модели и Ollama для тестов не нужны: всё тяжёлое в тестах замокано, а тесты с метками `manual` и `slow` по умолчанию пропускаются.

### Проверки перед пушем

```powershell
.venv\Scripts\python.exe -m ruff check jarvis tests
.venv\Scripts\python.exe -m pyright <изменённые файлы>
.venv\Scripts\python.exe -m pytest -q
```

Эталон на 2026-11-03: **6726 passed, 14 skipped, 10 deselected**, около 3 минут. В CI (`.github/workflows/ci.yml`) обязательны все три проверки. Учти, что в `jarvis/app.py` уже есть 9 старых ошибок pyright (задача P2-3).

### Запуск дома

Только из `.venv`. Глобальный `python` падает: в его site-packages нет модели wake word.

```powershell
$env:JARVIS_DUMP_LLM_REQUEST = "1"; .venv\Scripts\python.exe -m jarvis
```

### Где логи

| Файл | Что внутри |
|---|---|
| `jarvis.log.jsonl` в корне репозитория | Структурированный лог, время в UTC (дома UTC+1). Сюда же пишут и тесты: живые сессии ищи по `data dir: ...\AppData\Roaming\Jarvis` |
| `%APPDATA%\Jarvis\logs\jarvis.log` | Тот же лог текстом, локальное время, с трейсбеками ошибок |
| `%APPDATA%\Jarvis\debug\last_llm_request.json` | Последний запрос к модели: промпт, память, история, вызовы инструментов. Только с `JARVIS_DUMP_LLM_REQUEST=1`. Разобрать: `python -m jarvis.dev.llm_replay` |
| `%APPDATA%\Jarvis\memory\memory.db`, `collections.db` | Память и сохранённые списки. Тексты зашифрованы DPAPI, читаются только дома через `MemoryStore` / `CollectionStore` |

Сами реплики в лог не пишутся (приватность), только длина и решения роутера. Текст реплик, которые ушли в модель, есть в дампе.

## Бэклог

### P1 — заметно мешает

**P1-1. Сохранение страницы идёт 40–98 секунд. [Работа → Дом]**
`save_page_knowledge` выполнялся 98 с, 44 с и 40 с: почти всё время уходит на разбор страницы моделью в `jarvis/memory/page_extractor.py` (страница режется на части, каждую `qwen3:8b` превращает в JSON по `RESPONSE_SCHEMA`). Всё это время пользователь ждёт молча.
- Работа: сократить вход (`readable` уже даёт ~3500 символов из 6500, можно резать сильнее), проверить размер промпта и схемы, сразу сказать «читаю страницу, это займёт около минуты», а разбор вести в фоне. Тесты: замокать LLM, проверить, что ответ пользователю не ждёт разбора.
- Дом: замерить время по логу `[page_extractor]` и `save_page_knowledge ok in … ms`.

**P1-2. Модель говорит «сделал», но инструмент не вызывает. [Работа → Дом]**
На «…Барочку назови» модель ответила «Назову этот…», а `name_saved_list` не вызвала: у списка имени нет. Шаблоны в `jarvis/tools/local/saved_lists.py` (около строки 759) ловят только «назови (этот) список X».
- Работа: добавить шаблоны «назови его/её/это X», «X назови»; уточнить описание `name_saved_list`. Проверка — `tests/tools/local/test_saved_lists.py::test_mark_patterns` и соседние.
- Шире: правило системного промпта «ACTION → CALL the tool» модель нарушает. Можно ловить в роутере ответы-обещания без вызова инструмента («назову», «отметил», «открываю») и делать повторный запрос.

**P1-3. После падения автоперезапуск упирается в блокировку экземпляра. [Работа]**
15:32: запуск упал на загрузке wake word, а перезапуски 2 и 3 из `jarvis/__main__.py` получили «instance lock already held» и показали окно ошибки, потому что упавший запуск не освободил `jarvis.lock`.
- Найти в `jarvis/app.py`, где берётся `acquire_instance_lock`, и освобождать блокировку на пути «module load failed». Или не перезапускать при ошибке конфигурации/окружения: повтор её всё равно не исправит.
- Тест: падение загрузки модулей → блокировка освобождена.

**P1-4. Устаревший факт при повторном сохранении страницы. [Работа]**
В памяти лежат сразу «Saved checklist … (78 items)» и «… (36 items)» для одной страницы. `_remember_collection` в `jarvis/tools/local/web_knowledge.py` при пересохранении добавляет новый факт, а не заменяет старый с тегом `collection:<id>`.
- Исправить: найти факт по тегу `collection:<id>`, обновить его (`MemoryStore.update`) или удалить и создать заново.
- Тест: сохранить ту же страницу дважды → один факт, с новым числом пунктов.
- Дом: удалить старый факт «78 items» из памяти (как в чистке 03.11).

### P2 — качество и техдолг

**P2-1. Запасной путь извлечения знаний сохраняет сырую страницу. [Работа]**
`KnowledgeExtractor._save_plain_text_fallback` (`jarvis/memory/knowledge_extractor.py:333`) при битом JSON от модели кладёт в память до 5000 символов страницы вместе с меню и подвалом. После обрезки фактов (`5a478d4`) промпт это уже не раздувает, но в памяти лежит мусор. Сохранять только заголовок, URL и короткую выжимку из `readable`. Битый JSON можно убрать передачей `format`, как это сделано в `page_extractor`.

**P2-2. Тесты пишут в `jarvis.log.jsonl` в корне репозитория. [Работа]**
В режиме разработки JSON-лог пишется в текущую папку (`jarvis/app.py`, около строки 445), и прогон тестов засоряет живой лог. Писать в `data_path("logs", ...)` всегда, или в `tests/conftest.py` направлять в `tmp_path`.

**P2-3. Девять ошибок pyright в `jarvis/app.py`. [Работа]**
Строки ~1628–1653 и 1731 (`proactive_engine` типизирован как `object`), 2772 (`APILLMClient` против `OllamaClient`), 2958 (`_game_mode` у `Tool`). Ошибки из старых коммитов, но CI их блокирует.

**P2-4. Предупреждение в тестах. [Работа]**
`tests/ui/test_app.py::test_amplitude_latch_shared_reference`: «coroutine AsyncMockMixin._execute_mock_call was never awaited». Мок вызывается, но не ожидается, поэтому тест проверяет меньше, чем кажется.

**P2-5. STT искажает глагол команды. [Работа]**
STT пишет «Открый» и «Открою» вместо «Открой», и такие фразы мимо шаблонов уходят в модель (+3–4 с). В `_normalize` (`jarvis/llm/intent_router.py:241`) приводить частые искажения к правильной форме. Тест — `tests/tools/test_voice_routing_collisions.py`.

**P2-6. Запуск не из `.venv`. [Работа]**
В корне лежат неотслеживаемые `run_jarvis.ps1` и `home_check*.ps1`. Решить: закоммитить один официальный скрипт запуска через `.venv\Scripts\python.exe` (или дополнить `start-jarvis.ps1`) и при старте не из venv выдавать понятную подсказку, а не трейсбек про модель wake word.

**P2-7. Jarvis часто переспрашивает. [Дом]**
«Повторите» звучало при уверенности распознавания 0,42, 0,47, 0,50 и 0,69. Последний случай — длинная фраза из 45 символов. Посмотреть порог clarify в конфиге STT и, возможно, учитывать длину фразы.

Фразы для живой сессии. Ожидаемое поведение — в скобках.

1. «Отметь в игре Блич пройти вторую главу в сюжете» (отмечается «И Дождь прошёл»)

5. «Меня зовут <своё настоящее имя>» (в память и профиль записывается именно имя; проверка `7a7dd98`. Фраза меняет профиль, поэтому называй настоящее имя)

7. Выход (прощание на языке разговора)
