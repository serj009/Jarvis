## 1. Как работать в двух местах

| | Дом | Работа |
|---|---|---|
| Что есть | Полная среда: GPU RTX 3060, Ollama + `qwen3:8b`, микрофон, модели STT/TTS/wake word | Только код и тесты |
| Что делать | Живые проверки голосом, чтение логов, замеры, настройка порогов | Код, юнит-тесты, рефакторинг, документация |
| Как понять, что готово | Поведение в логе живой сессии | `ruff`, `pyright` и `pytest` зелёные |

Каждая задача помечена:

- **[Работа]** — можно сделать и проверить тестами без домашнего ПК;
- **[Дом]** — нужен живой запуск Jarvis;
- **[Работа → Дом]** — код пишется на работе, финальная проверка голосом дома.

### Цикл

1. **Работа:** `git pull`, взять задачу из текущего этапа, написать код и тест, прогнать проверки, `git push`.
2. **Дом:** `git pull`, запустить Jarvis с дампом запросов, проговорить фразы из раздела 8, закрыть Jarvis.
3. **Дом:** попросить Claude «проверь логи» (или прочитать самому — таблица «Где логи»).
4. Обновить этот файл: закрытое — в раздел 9, новые находки — в бэклог.

### Среда на работе (один раз)

```powershell
git clone https://github.com/serj009/Jarvis.git
cd Jarvis
git checkout amazonq
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Python 3.14, как дома. Модели и Ollama для тестов не нужны: тяжёлое замокано, тесты `manual` и `slow` по умолчанию пропускаются.

Не держи на рабочем ПК личные файлы: `my_preferences.yaml`, образцы голосов, базы памяти. В git их нет и не должно быть.

### Проверки перед пушем

```powershell
.venv\Scripts\python.exe -m ruff check jarvis tests
.venv\Scripts\python.exe -m pyright <изменённые файлы>
.venv\Scripts\python.exe -m pytest -q
```

Эталон на 2026-11-03: **6726 passed, 14 skipped, 10 deselected**, около 3 минут. В CI (`.github/workflows/ci.yml`) обязательны все три проверки. В `jarvis/app.py` уже есть 9 старых ошибок pyright (задача B-P2-3).

### Запуск дома

Только из `.venv`. Глобальный `python` падает: в его site-packages нет модели wake word.

```powershell
$env:JARVIS_DUMP_LLM_REQUEST = "1"; .venv\Scripts\python.exe -m jarvis
```

### Где логи

| Файл | Что внутри |
|---|---|
| `jarvis.log.jsonl` в корне репозитория | Структурированный лог, время в UTC (дома UTC+1). Сюда же пишут и тесты: живые сессии ищи по `data dir: ...\AppData\Roaming\Jarvis` |
| `%APPDATA%\Jarvis\logs\jarvis.log` | Тот же лог текстом, локальное время, с трейсбеками |
| `%APPDATA%\Jarvis\debug\last_llm_request.json` | Последний запрос к модели (промпт, память, история, вызовы инструментов), только с `JARVIS_DUMP_LLM_REQUEST=1`. Разбор: `python -m jarvis.dev.llm_replay` |
| `%APPDATA%\Jarvis\memory\memory.db`, `collections.db` | Память и сохранённые списки. Тексты зашифрованы DPAPI, читаются только дома через `MemoryStore` / `CollectionStore` |

Сами реплики в лог не пишутся (приватность), только длина и решения роутера. Текст реплик, ушедших в модель, есть в дампе.

## 2. Цель: что значит «готово»

**v1.0** — это (предложение, см. решение D1 в разделе 6):

1. **Устанавливается как программа.** `Jarvis-Setup-1.0.0.exe`: ставится, запускается, удаляется; при первом запуске находит Ollama или предлагает её поставить и скачивает модель. Это фаза 7 из `BUILD.md`.
2. **Стабилен в ежедневной работе.** Неделя домашнего использования без падений и без «зависших» состояний; сон/пробуждение освобождают VRAM; после сбоя модуля голосовой цикл продолжает работать.
3. **Проверен регрессией.** Набор контрольных фраз ru/uk/en: автоматически на уровне роутера (работа) и вживую по чек-листу (дом), всё зелёное.
4. **Документация совпадает с кодом:** `SPEC.md`, `README.md`, `CHANGELOG.md`.
5. **Выпущен:** версия `1.0.0`, тег, релиз на GitHub.

Всё, что не входит в эти пять пунктов, идёт после v1.0 (раздел 5).
