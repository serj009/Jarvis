## 1. Как работать в двух местах

| | Дом | Работа |
|---|---|---|
| Что есть | Полная среда: GPU RTX 3060, Ollama + `qwen3:8b`, микрофон, модели STT/TTS/wake word | Только код и тесты |
| Что делать | Живые проверки голосом, чтение логов, замеры, настройка порогов | Код, юнит-тесты, рефакторинг, документация |
| Как понять, что готово | Поведение в логе живой сессии | `ruff`, `pyright` и `pytest` зелёные |

Каждая задача помечена:

- **[Работа]** — можно сделать и проверить тестами без домашнего ПК;
- **[Дом]** — нужен живой запуск Jarvis;
- **[Работа → Дом]** — код пишется на работе, финальная проверка голосом дома.

### Цикл

1. **Работа:** `git pull`, взять задачу из текущего этапа, написать код и тест, прогнать проверки, `git push`.
2. **Дом:** `git pull`, запустить Jarvis с дампом запросов, проговорить фразы из раздела 6, закрыть Jarvis.
3. **Дом:** попросить Claude «проверь логи» (или прочитать самому — таблица «Где логи»).
4. Обновить этот файл: закрытое удалить, новые находки — в бэклог. Вопрос, который может решить только владелец, — в бэклог с пометкой «нужно решение»; пока решения нет, по задаче не работать.

### Работа из браузера (облачная сессия Claude Code)

Без установки на рабочем ПК: claude.ai/code → репозиторий `serj009/Jarvis`, ветка `amazonq`. Claude работает в облачной копии репозитория (Linux): правит код, гоняет `ruff` / `pyright` / `pytest` и пушит в ветку. Живого Jarvis там нет (ни GPU, ни Ollama, ни микрофона, ни твоих данных), поэтому брать задачи **[Работа]**; у **[Работа → Дом]** — только кодовую часть. Тесты на Linux: платформенные (Windows) там пропускаются или не запускаются — финальный прогон всё равно дома на Windows. Дома: `git pull` и цикл выше (шаги 2–4).

### Среда на работе (один раз)

```powershell
git clone https://github.com/serj009/Jarvis.git
cd Jarvis
git checkout amazonq
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Python 3.14, как дома. Модели и Ollama для тестов не нужны: тяжёлое замокано, тесты `manual` и `slow` по умолчанию пропускаются.

Не держи на рабочем ПК личные файлы: `my_preferences.yaml`, образцы голосов, базы памяти. В git их нет и не должно быть.

### Проверки перед пушем

```powershell
.venv\Scripts\python.exe -m ruff check jarvis tests
.venv\Scripts\python.exe -m pyright <изменённые файлы>
.venv\Scripts\python.exe -m pytest -q
```

Эталон на 2026-11-03: **6766 passed, 14 skipped, 10 deselected**, около 3 минут. В CI (`.github/workflows/ci.yml`, Windows и Ubuntu) обязательны все три проверки. В `jarvis/` есть старые ошибки pyright (задача M2-1) — проверяй pyright только по своим файлам.

### Запуск дома

Только из `.venv`. Глобальный `python` падает: в его site-packages нет модели wake word.

```powershell
$env:JARVIS_DUMP_LLM_REQUEST = "1"; .venv\Scripts\python.exe -m jarvis
```

### Где логи

| Файл | Что внутри |
|---|---|
| `%APPDATA%\Jarvis\logs\jarvis.log.jsonl` | Структурированный лог, время в UTC (дома UTC+1). Тесты сюда не пишут. До 2026-11-05 файл лежал в корне репозитория (`jarvis.log.jsonl`) вперемешку с логами тестов |
| `%APPDATA%\Jarvis\logs\jarvis.log` | Тот же лог текстом, локальное время, с трейсбеками |
| `%APPDATA%\Jarvis\debug\last_llm_request.json` | Последний запрос к модели (промпт, память, история, вызовы инструментов), только с `JARVIS_DUMP_LLM_REQUEST=1`. Разбор: `python -m jarvis.dev.llm_replay` |
| `%APPDATA%\Jarvis\memory\memory.db`, `collections.db` | Память и сохранённые списки. Тексты зашифрованы DPAPI, читаются только дома через `MemoryStore` / `CollectionStore` |

Сами реплики в лог не пишутся (приватность), только длина и решения роутера. Текст реплик, ушедших в модель, есть в дампе.

## 2. Цель: что значит «готово»

**v1.0** — это:

1. **Устанавливается как программа.** `Jarvis-Setup-1.0.0.exe`: ставится, запускается, удаляется; при первом запуске находит Ollama или предлагает её поставить и скачивает модель. Это фаза 7 из `BUILD.md`.
2. **Стабилен в ежедневной работе.** Неделя домашнего использования без падений и без «зависших» состояний; сон/пробуждение освобождают VRAM; после сбоя модуля голосовой цикл продолжает работать.
3. **Проверен регрессией.** Набор контрольных фраз ru/uk/en: автоматически на уровне роутера (работа) и вживую по чек-листу (дом), всё зелёное.
4. **Документация совпадает с кодом:** `SPEC.md`, `README.md`, `CHANGELOG.md`.
5. **Выпущен:** версия `1.0.0`, тег, релиз на GitHub.

Всё, что не входит в эти пять пунктов, идёт после v1.0 (раздел 4).

## 6. Проверка дома

Фразы для живой сессии; ожидаемое поведение — в скобках. В этапе M3 список расширяется до 14 сценариев.

Новые пункты добавляются сюда вместе с задачей, которую они проверяют.

- **Таймер и напоминание на языке запроса (B-P2-9).** «Поставь таймер на одну минуту» → через минуту по-русски: «Таймер истёк, сэр.» (или «Таймер «…» истёк, сэр!», если модель дала таймеру имя). «Постав таймер на півхвилини» → по-украински («Таймер спрацював, сер.»). «Напомни через две минуты купить молоко» → «Напоминаю, сэр: купить молоко». Английских «Timer … is done, sir!» быть не должно.
- **Погода (B-P1-9).** «Какая погода?» → по-русски, со шкалой: «Сейчас 7 градусов по Цельсию, пасмурно, сэр.»; «Яка погода?» → по-українськи. Сравнить с прогнозом за окном. В логе должна быть строка `weather: location from IP: <город>, ... (<широта>, <долгота>)` и `detected location saved to config`, а в `%APPDATA%\Jarvis\config.json` — `weather.unit = "celsius"` и заполненные `latitude` / `longitude`. Если город не тот (VPN, провайдер) — задать координаты в Настройки → Общие. Если строк `weather:` в логе нет совсем, значит, инструмент не вызывался и «86 градусов» модель придумала сама: записать в бэклог. Если есть `ipapi.co gave no location (reason: RateLimited)` — нужен другой способ определения места.
- **Повтор упавшей части страницы (B-P2-10).** Специально не воспроизвести (нужна ошибка 500 от Ollama); при следующем сохранении большой страницы посмотреть в логе: если есть `part N/M failed; retrying once in 15 s`, то за ней должен идти либо успешный разбор, либо `failed again; skipped`, а в объявлении — «Не прочитано частей страницы: 1 из 9, список может быть неполным».
- **Выход во время чтения страницы (B-P2-8).** «Запомни эту страницу» на большой странице, через 20–30 с — выход из трея. В логе: `shutdown: stopped reading <адрес>; the page is NOT saved`, после неё никаких `[page_extractor] ... part N/M`, Jarvis закрывается без задержки.
- **JSON-лог в папке данных (B-P2-2).** После запуска дома строки живой сессии пишутся в `%APPDATA%\Jarvis\logs\jarvis.log.jsonl`, каждая строка один раз (раньше каждая была дважды), а `jarvis.log.jsonl` в корне репозитория больше не растёт (старый файл можно удалить).
- **Искажённый глагол (B-P2-5).** Если STT напишет «Открый блокнот» / «Открою калькулятор» / «Закрою блокнот», команда должна выполниться сразу, без похода в модель: в логе роутер выбирает шаблон, `last_llm_request.json` не обновляется.
- **«Сэр» вместо «sir» (B-P2-13).** По-русски: «Подтвердите», «Громкость: 50%», «Скриншот», «До свидания» — в конце звучит «сэр», а не искажённое английское слово; по-украински — «сер».

Скажу, когда сохраню.»; при наведении на значок в трее — «Читаю «…»: часть 3 из 9», номер растёт; «как там страница?» отвечает тем же; в конце — уведомление и голосом «Сохранил «…», пунктов: N». В логе — `[web_knowledge] reading <адрес>: part N/M`.
- **Гайды Steam (B-P1-11).** Гайд по Uncharted → «Запомни эту страницу» → 101 пункт (было 221), с описаниями «как получить» из гайда; Bleach — по-прежнему 36. В логе: `Steam guide for app <appid>`, `[steam] app <appid>: N official achievements`, `Steam app ...: N official achievements (the guide gave M items)`. **Разбор страницы статистики Steam написан вслепую** (из облака steamcommunity.com недоступен): если в логе `0 official achievements` или `unavailable`, сохранить страницу `https://steamcommunity.com/stats/<appid>/achievements/?l=russian` (Ctrl+S) и отдать Claude — поправить `parse_achievements`.
- **Запуск не из `.venv` (B-P2-6, M2-2).** Один раз запустить глобальным `python -m jarvis` из папки проекта: одно окно ошибки, в тексте — «Start it with: …\.venv\Scripts\python.exe -m jarvis (or start-jarvis.ps1)», и Jarvis **не** перезапускается ещё дважды (в логе `cannot start in this environment; not restarting`).
